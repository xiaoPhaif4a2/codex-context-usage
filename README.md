# Codex 上下文指示器

Windows 上的独立底部浮层，外观参考 DeepSeek Harness 的圆环图标。显示「圆环 + 使用百分比 + 压缩次数 / 当前建议 + 对话名称」，例如「27% · 压1 · 继续 · 继续讨论」。跟随前台 Codex / ChatGPT 桌面窗口的底边显示；切到其他应用或最小化窗口时隐藏。点击查看读数、压缩前后变化、建议依据，以及留存进度 / 交接文档的提示词。

这是伴随工具，**不是 Codex 输入框的原生组件**。位置依据窗口底边计算，不能识别输入框；打开侧栏、调整布局时可拖动指示器重新定位。自动读取 Codex 桌面导航日志，切换到哪个对话就显示哪个对话的用量；后台其他对话生成消息不会改变监控对象。

## 启动

需要 Python 3.10+ 和 Tkinter（Windows 官方 Python 安装通常已包含），无需第三方依赖或 API Key。

下载仓库 ZIP 并解压，或者使用 Git：

```powershell
git clone https://github.com/xiaoPhaif4a2/codex-context-usage.git
cd codex-context-usage
```

在项目目录执行：

```powershell
python -m context_indicator
```

也可以双击 `start.pyw`，无终端窗口启动（需已关联 Python `.pyw` 文件）。

或者：

```powershell
.\start.ps1
```

启动命令先启用轻量窗口监听。Codex 窗口打开时启动独立指示器进程，将 Codex 置于前台后在窗口底部约 74% 宽度处出现圆环。可拖动调整位置，右键选择「恢复底部位置」或「停止跟随并退出」。只有浮层匹配到前台 Codex.exe / ChatGPT.exe 窗口时才显示，进程名称不同的桌面版本需调整 `context_indicator/windows.py` 的匹配列表。

每个项目只允许一个监听和一个浮层实例，重复启动会提示已在运行。

### 自动启动

首次配置一次，之后无需每次手动启动脚本：

```powershell
python -m context_indicator --enable-autostart
```

也可在详情窗口勾选“登录时启用轻量监听（指示器随 Codex 开闭）”。使用当前用户的 Windows `Run` 启动项，无需管理员权限，不修改 Codex 程序。**登录启动的是轻量监听，指示器随 Codex 窗口启动和关闭**：

- Codex 没打开：只有监听进程，每秒检查一次窗口，不读取会话日志，不创建指示器。
- 打开 Codex：启动指示器进程，开始读取用量；不要求从特定快捷方式打开 Codex。
- 切到其他应用 / 最小化：隐藏浮层，保留指示器，不视为关闭 Codex。
- 关闭最后一个 Codex 主窗口：停止指示器进程和用量读取；再次打开时重新启动。多窗口时关闭其中一个不会停止指示器。
- 右键“停止跟随并退出”：结束监听和指示器，本次登录不再自动启动；下次登录仍按启动项配置运行。

窗口变化通常在一次轮询（约 1 秒）内处理。只检查有标题、可见且非附属的 Codex 顶层窗口；无标题 / 隐藏窗和 CLI 辅助进程不作为主窗口。Windows 可能稍微延后执行登录启动项。

查看 / 关闭自启动：

```powershell
python -m context_indicator --autostart-status
python -m context_indicator --disable-autostart
```

启动项指向当前安装目录的 `start.pyw` 和 Python 的 `pythonw.exe`，不依赖终端工作目录或 `.pyw` 文件关联；路径包含空格也可用。移动项目或 Python 后需重新启用以更新路径。关闭自启动需取消勾选或执行关闭命令，这只影响后续登录，本次跟随继续。删除项目之前建议先关闭自启动。可选的 `--web` 面板独立运行，不跟随桌面窗口关闭。

参考：[Windows 登录启动项说明](https://learn.microsoft.com/windows/win32/setupapi/run-and-runonce-registry-keys)。

默认跟随 Codex 当前页面，支持跨项目切换。名称从本地 `state_*.sqlite` 的命名元数据读取，`session_index.jsonl` 作为备用。底部、悬停说明和详情均显示名称；详情下拉列表显示「名称 · 使用百分比」。同名对话附带项目和序号区分，不展示 UUID。下拉选择会通过 `codex://threads/...` 打开对应 Codex 对话，并等待实际页面导航信号再更新用量。

旧版保存的会话 ID 和环境变量 `CODEX_THREAD_ID` 不会将指示器固定到启动对话。位置和阈值仍保存在项目 `.context-indicator.json`，不会修改 Codex 配置。

仅列出某个项目的对话（其他项目页面会显示未知）：

```powershell
python -m context_indicator --project C:\path\to\project --project-only
```

初始容量阈值默认 70% 关注容量、85% 高占用，可通过详情窗口修改，或首次启动时设置：

```powershell
python -m context_indicator --warning 65 --critical 80
```

已保存的项目阈值优先于命令行初始值。单次高占用只改变圆环颜色，不弹出交接要求。只有“建议留存进度”和“建议阶段后交接”才显示提醒；同一建议不会随每次刷新反复弹出。提醒仅在 Codex 窗口处于前台时显示。

预览外观（明确使用示例数据）：

```powershell
python -m context_indicator --demo
```

也保留可选的浏览器面板：

```powershell
python -m context_indicator --web --open
```

该面板默认地址 `http://127.0.0.1:8765`。端口占用时可添加 `--port 0` 自动分配。按 Ctrl+C 停止服务；浏览器面板阈值保存在浏览器中，独立于浮层设置。

## 什么时候留存进度或切换对话

这些是本工具的经验规则，**不是 OpenAI 的官方交接标准，也不能证明回答质量下降**。占用率与交接建议分开显示：一次高占用、一次自动压缩都不要求换对话。

| 信号（默认配置） | 建议 | 操作 |
| --- | --- | --- |
| 占用低于 70%，没有其他信号；或只压缩一次且容量已恢复 | 继续工作 | 留在原对话 |
| 单次占用达到 70% / 85% | 留意容量 | 可以继续，等待自动压缩；不弹交接提醒 |
| 连续 3 轮已完成请求的最终占用达到 85%；或自上次确认留存后又压缩 2 次 | 建议留存进度 | 在本轮或阶段结束后保存 `HANDOFF.md`，可继续原对话 |
| 最近 5 轮请求内压缩至少 2 次；或累计压缩至少 3 次且占用再次达到 70% | 建议阶段后交接 | 到合适的暂停点生成并核对文档，再新建对话 |
| 用户主动标记遗漏要求 / 混淆状态 | 建议阶段后交接 | 明确记录纠正内容，核对文档后切换；标记可以撤销 |

高等级规则优先于低等级规则。轮次来自日志的 `task_started` / `turn_context.turn_id` 与 `task_complete`：一条用户请求算一轮，工具调用、重复事件、后台轮询不增加轮次。缺少轮次事件的旧日志不臆造“连续 3 轮”或“最近 5 轮”的证据。压缩或模型切换会重置持续高占用的统计；无新读数时不沿用旧占用率。

如果本轮仍在执行，建议明确显示“先等待完成或主动暂停”。一轮完成只表示这次请求结束，工具不能判断整个项目阶段是否完成。即使提示交接，也无需突然中断正在进行的任务。

详情显示压缩次数、最近压缩时间，以及“压缩前占用 → 压缩后首个有效读数”。例如 `87.3% → 3.9%`，继续执行后当前读数可能已增长到 20%。这表示同一对话的模型上下文已缩短；聊天界面的原历史仍可见。日志不区分触发方式时，手动和自动压缩统一计入次数。

两个按钮的用途不同：

1. **留存进度（留在当前对话）**：复制提示词，粘贴发送，更新 `HANDOFF.md` 后继续原对话。适合阶段完成或长任务中途保存。
2. **准备交接（新对话继续）**：复制交接提示词，粘贴发送，核对文档中的目标、决定、剩余工作和验证结果，再新建对话输入：`请读取 HANDOFF.md，按其中的目标、约束和剩余事项继续工作。`

**复制不等于文档已生成。** 查看文件确认完成后，才点击“我已确认文档保存完成”。这会记录该对话的保存位置，避免同一批工作再次要求留存；后续新增的持续高占用 / 压缩仍会触发建议。确认保存不会撤销已有的阶段后交接建议或遗漏标记。

确认状态和遗漏标记按对话保存在启动项目的 `.context-indicator-advice.json`，重启后保留，已排除在 Git 之外。详情显示最近一次确认时间。工具不检查 `HANDOFF.md` 的内容或仅因文件存在就宣称保存完成，也不自动发送消息、生成文档或创建新对话。

## 数据口径与限制

读取 `${CODEX_HOME}/sessions/**/*.jsonl`，默认 `~/.codex/sessions`，只保留主对话元数据、token、轮次与压缩统计。浮层每 0.5 秒检查，增量读取日志，等待不完整 JSON 行写完后再处理。同一对话存在多个日志副本时，优先使用元数据指定的 `rollout_path`，否则选择最近的有效主日志，每个对话只显示一行。子代理、归档目录和云端会话不纳入用量显示；默认包含所有项目。日志读取过程中经过会话内容，但不保留或展示消息、工具输出、压缩摘要，也不访问 `auth.json`。

自动跟随使用 `%LOCALAPPDATA%/Codex/Logs` 中的桌面主进程日志（自动兼容 Store 的 LocalCache 目录）。只提取 `browser sidebar owner sync` 事件的 `ownerRoutePath`、窗口 / 进程编号和时间；后台 App Server 的 `conversationId` 不作为页面选择依据。可用 `--desktop-logs C:\path\to\Logs` 指定目录。没有有效导航信号时显示未知，不回退到最近生成消息的对话。多个主窗口无法确定焦点时也显示未知。

```text
使用比例 = last_token_usage.total_tokens / model_context_window × 100%
```

最近一次调用的输入与输出总量近似反映上下文占用；这不是模型此刻全部内部状态的精确计量。缓存输入仍占上下文，不能扣除；`total_token_usage` 是累计消耗，不能当占用率。采用日志报告的窗口大小，不写死模型窗口。缺少有效用量 / 窗口时显示未知；压缩或模型切换后等待新读数。窗口在长回复期间可能只报告最近一次完成请求，页面切换本身也不产生 token 读数。

本地 JSONL 和桌面导航日志格式是观察到的实现细节，未来版本可能变化。已在本机 26.930 桌面版的真实导航事件上核对。官方 App Server 文档提供 `thread/tokenUsage/updated` 事件，但本工具没有接管桌面程序的 App Server 连接，使用现有日志作为数据源。

参考：[App Server 用量事件](https://learn.chatgpt.com/docs/app-server)、[终端状态栏配置](https://learn.chatgpt.com/docs/config-file/config-sample)、[MCP 自定义 UI](https://developers.openai.com/plugins/build/chatgpt-ui)。
